# Devtool Launch Pack

## Purpose

Prepare a small developer-tool repository for a clear, honest public launch.

Use this skill for AI devtools, agent utilities, CLI tools, prompt tools, eval tools, and workflow templates.

## Inputs

- Repository README, file tree, demo command, metadata, and current status.
- Target audience and main pain point.
- Verification results if available.

## Workflow

1. State the tool in one sentence: who it helps, what pain it solves, and how to try it.
2. Check README sections: why, install, quickstart, examples, API or interface, FAQ, contributing, license.
3. Check the demo command from a clean checkout when possible.
4. Propose GitHub description, topics, release notes, and first three issues.
5. Draft launch copy for relevant communities without spam, hype, or fake scarcity.
6. List post-launch metrics to record: views, clones, stars, forks, issues, and referrers.

## Output

Produce Markdown with these sections:

- Launch Readiness
- README Fixes
- GitHub Metadata
- Release Notes Draft
- Launch Copy
- First Issues
- Metrics Plan

Make the launch understandable to a stranger in under one minute.

## Validation

- The quickstart command is present and realistic.
- Launch copy names a real pain point and avoids spam tactics.
- Topics are relevant and not keyword stuffing.
- Release notes describe user-visible value.
- Any unverified claims are removed or marked as not tested.
